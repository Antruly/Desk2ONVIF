# Desk2ONVIF 0.1.0

把 Windows 桌面模拟成一台 **ONVIF Profile S 摄像机**：桌面画面 → H.264 → RTSP
推流，同时让海康/大华等 NVR 能自动发现并作为 IP 通道添加。

两种装法，用哪个都行（这份说明两边通用）：

| | 怎么做 | 配置放在哪 |
|---|---|---|
| **安装包** `Desk2ONVIF_Setup_0.1.0.exe` | 双击装即可，**不问管理员权限**，装到 `%LOCALAPPDATA%\Programs\Desk2ONVIF`，带开始菜单项和卸载程序 | 装好的目录里的 `config.json` |
| **绿色版** `Desk2ONVIF-0.1.0-win64.zip` | 解压到任意目录就能跑；想搬到别的机器，**整个目录拷走**即可 | 同上，跟着目录走 |

两种装法装出来的文件完全一样。绿色版没有安装程序，所以下面「静默安装」那一节可以跳过。

---

## 先跑这两个

**1. 看看这台机器能不能录**（第一次一定要跑）

```
双击  list-displays.bat
```

它会列出每个显示输出，**并且逐个真的建一次捕获会话**来探测能不能录。
记下你想录的那个的序号，待会儿用 `start.bat --display 1` 指定。

> 虚拟显示器（向日葵/ToDesk 的虚拟屏、部分远程桌面适配器）**不支持桌面复制**。
> 选中它们的结果是**黑屏或定格，而任何地方都不报错** —— 因为 `DuplicateOutput`
> 本身是成功的，只是一帧都不来。所以这一步不要跳过。

**2. 启动**

```
双击  start.bat
```

起来之后屏幕上会打出地址，浏览器打开 **Web 控制台**就能看到画面和配置：

| | 地址 |
|---|---|
| Web 控制台 | `http://<本机IP>:8080/` |
| 主码流 | `rtsp://<本机IP>:554/live` |
| 子码流 | `rtsp://<本机IP>:554/live_sub` |
| ONVIF | `http://<本机IP>:8080/onvif/device_service` |

打开 Web 控制台会**先要你登录**：默认 `admin` / `admin`。**装完请改掉** ——
这一对是公开的出厂值，而 `start.bat` 默认监听 `0.0.0.0`（怎么改、以及它和 NVR
那套凭据的区别，见下面「安全」）。登进去的**首页就是预览**，能直接看到桌面
画面；另有「状态」和「配置」两页，顶栏可以退出登录。

本机拉流试一下（`ffplay` 随便找个装了的都行）：

```powershell
ffplay -rtsp_transport tcp rtsp://127.0.0.1:554/live
```

**Ctrl+C 停止。** 不要直接关窗口，那样 RTSP 的 `Bye` 不会发出去。

## 每个脚本干什么

| 文件 | 用途 |
|---|---|
| `start.bat` | 正常启动：RTSP + Web + ONVIF。**监听 0.0.0.0**，局域网可访问 |
| `start-local.bat` | 同上，但只监听 `127.0.0.1`。**不想让局域网碰你的机器时用这个** |
| `list-displays.bat` | 列出显示输出 + 探测能不能录（第一次先跑这个） |
| `selfcheck.bat` | 依赖自检。起不来时跑它，能把"DLL 缺失/端口被占/没有可录输出"分开 |
| `firewall-print.bat` | 把需要的防火墙命令**打出来**。只读，不动你的防火墙 |

想加参数直接跟在后面，会原样传给程序（`desk2onvif.exe --help` 是完整清单）：

```powershell
.\start.bat --display 1 --fps 60 --bitrate 8000
.\start.bat -RtspPort 8554          # 554 被别的 RTSP 服务占了的话
.\start.bat -NoOnvif                # 只推流，不做 ONVIF 设备模拟
```

## 加进 NVR（海康 / 大华）

1. 确认 NVR 和这台机器在**同一个网段**
2. 先跑一次 **`firewall-print.bat`**，把打出来的命令在**管理员**命令行里执行
   （它只对同网段放行，不是对全世界开放）
3. 在 NVR 上用 **ONVIF / 自定义协议** 添加通道，地址填 `http://<本机IP>:8080/onvif/device_service`
   - 用户名 `admin`，口令 `admin` —— 这是 **NVR 用的 ONVIF 凭据**，和控制台的
     登录是**两套**（见下面「安全」那张表）。**装完请改掉。**
4. NVR 一般会自己搜到（WS-Discovery 组播），搜不到就手工填上面的地址

> **NVR 搜不到或连不上时，先查防火墙。** 本机 ffplay 走的是回环接口、不受
> 防火墙影响，所以「本机一切正常、别的机器连不上」正是它的典型症状。

## 改配置

Web 控制台上**改完就能存**。其中：

- **ONVIF 身份与口令（厂商/型号/序列号/用户名/口令）—— 存完当场生效**，
  不用重启。NVR 那边不用重连。
- **Web 控制台的登录开关与用户名/口令 —— 也当场生效**，不用重启。注意它
  **不会把已经登录的人踢下线**（令牌签的是每进程一份的随机密钥，不是口令）；
  要立刻清空所有登录，只能重启程序。
- **其余（分辨率、帧率、码率、端口…）—— 要重启**。页面上会**逐项列出**
  哪几项还没生效，不是笼统一句"要重启"。

配置文件是 **这个目录下的 `config.json`**（不在 `%APPDATA%`，所以整个文件夹
是自包含的，拷到别的机器也不会和别处的配置打架）。**想恢复出厂设置，删掉它就行。**

> 码率是**改不了**的，这一点是实验证明过的，不是没做：FFmpeg 的 libx264
> 封装层不认运行中改 `bit_rate`，而 `x264_encoder_reconfig` 根本没从
> `avcodec-63.dll` 导出。这条链路上无解。

## 端口

| 端口 | 用途 |
|---|---|
| 554/tcp | RTSP（NVR 默认就用这个） |
| 8080/tcp | Web 控制台 + ONVIF SOAP |
| 3702/udp | WS-Discovery，NVR 靠它自动搜到设备 |

被占了就换：`start.bat -RtspPort 8554`。

3702 还被 **Windows 自带的 WS-Discovery** 占着（`fdPHost` 服务）—— 这是正常的，
两者能共存，程序已经处理了。

## 说清楚哪些验证过、哪些没有

**验证过**（`tests/rtsp_sub_e2e.ps1`，一次跑完，退出码 0）：

- 两路 RTSP 真的能拉、能解，主 2880x1920 / 子 540x360 各自 30fps，解码零报错
- ONVIF `GetProfiles` / `GetStreamUri` / Digest 401 挑战应答 **68 项**逐条严格解析
- **Web 控制台的登录契约 51 项**：哪条路该被 401 拦住、哪条路必须匿名可达
  （`/api/session`、静态资源）、两条快照路径各自的凭据、失败限速、登出
- WS-Discovery Probe → ProbeMatch 往返（XAddrs 真的可达）
- Web 契约 **77 项**：静态产物逐个验 MIME、`/api/config` 往返、逐路字段对账、
  HTTP 与 WebSocket 两条路的字段集必须一致
  （**97 项**是同一次运行再挂上两路拉流客户端之后的项数。有几项只在真的有人在
  推流时才验得到，所以这个数字取决于跑的那一刻有没有客户端在拉 —— 77 和 97
  都是"失败 0 项"，不是少验了）
- **浏览器里真的开了一遍**（`tests/browser/`，起本机 Chrome）：登录页渲染、
  路由守卫把未登录的人送回登录页并记住原目标、错口令给的是人话、
  登录后回到原来那一页、预览页 MSE 真的播起来
- **改 ONVIF 身份后换一个新 Digest 挑战去问，拿回来的就是新值**（不重启）

**没有验证**（我在开发机上做不到，需要你）：

- **真实海康/大华 NVR 的发现与拉流** —— 协议层能替的都替了，插上 NVR 那一下只能你来
- **锁屏 / 切分辨率 / 显示器休眠后的自动恢复** —— 代码路径是通的，统计里也一直有
  「会话重建 N 次」，但这三种情况没实测过

## 静默安装（批量部署用）

**用绿色版的话这一节整节跳过** —— 它没有安装程序。

```powershell
Desk2ONVIF_Setup_0.1.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART `
    /DIR="D:\apps\Desk2ONVIF" /LOG="$env:TEMP\d2o-install.log" `
    /D2ORTSPORT=554 /D2OHTTPPORT=8080 /D2OSCOPE=all /MERGETASKS=!desktopicon
```

| 参数 | 说明 |
|---|---|
| `/D2ORTSPORT` `/D2OHTTPPORT` | 端口，默认 `554` / `8080`。两个不能填成一样 |
| `/D2OSCOPE=all`（或 `lan`）/ `local` | 监听所有网卡，还是只监听 `127.0.0.1` |
| `/D2OUSER` `/D2OPASS` | ONVIF 凭据，默认 `admin` / `admin` |
| `/MERGETASKS=!desktopicon` | 不建桌面快捷方式（开始菜单项照建） |
| `/LOG=<路径>` | 安装日志。**静默安装下这是唯一能看到警告的地方** |
| `/DIR=<路径>` `/VERYSILENT` `/SUPPRESSMSGBOXES` `/NORESTART` | Inno 自己的开关 |

**口令请走环境变量，不要写 `/D2OPASS=`。** Inno 的开关解析不按 MSVC 那套
反斜杠转义规则来 —— 值里出现一个双引号会被当成引号分隔符吃掉，传进去的就不是
原样了。而口令里有引号或反斜杠是很正常的事，转义一旦没做对，写出来的
`config.json` 就是语法非法的，程序**直接拒绝启动**，用户看到的是"闪一下就没了"，
很难想到是自己口令里的一个引号。环境变量不过这一层解析：

```powershell
$env:DESK2ONVIF_USER     = 'admin'
$env:DESK2ONVIF_PASSWORD = 'A"b\c'     # 引号和反斜杠都能原样进去
Desk2ONVIF_Setup_0.1.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG="$env:TEMP\d2o.log"
```

优先级是 **命令行参数 > 环境变量 > 内置默认值**。口令**不写进日志**（日志经常被
贴进工单和聊天窗口）。

静默路径上有几处行为和交互式**不一样**，部署前值得知道：

- **端口被占用不会中止安装**，只在日志里写一行警告。无人值守时没人能回答
  "换个端口好吗"，中止是更坏的结果；真正的症状会在启动时出现（bind 失败），
  那时日志是唯一能看出原因的地方。
- **重装/升级会覆盖 `config.json`**，但旧的会先备份成 `config.json.bak`。
  因为向导页的端口默认值永远是 554/8080，一路回车就把你上次填的值洗掉了。
  真要保配置，升级前自己抄一份更稳妥。
- **静默卸载不问"要不要保留配置"，直接连配置一起删掉。** 只有交互式卸载才会问；
  选"否"的话配置会被复制到 `%APPDATA%\Desk2ONVIF\config.json`，下次重装不用再填。
上面三条其实都是同一条规矩的推论：**`/VERYSILENT` 下没有任何确认框会被自动回答，
它会一直等你点，把安装挂在那里** —— 没有报错、没有退出码（进程还没退）、日志最后
一行停在问句上、目标目录根本没建。这个症状和"安装程序坏了"长得一模一样。所以静默
路径上凡是需要确认的地方，答案一律由参数预先决定，或者干脆不问。

装和卸都不需要管理员权限，不弹 UAC。这是刻意的：程序要把 `config.json` 写在 exe
旁边（删掉它就是恢复出厂设置），装到 `Program Files` 的话每次存配置都要提权，
而失败的表现是"改了配置存不下来"，很难查。

## 安全

**Web 控制台要登录，但出厂用户名/口令是 `admin`/`admin`，而 `start.bat` 默认
监听 `0.0.0.0`** —— 在改掉口令之前，同一局域网内任何机器都能用这一对进来
**看你的桌面画面、读配置、改配置**。这一对就印在 `--help` 里，等于没有。

装完请先改它（控制台 → 配置 → 登录用户名/登录口令，**存完当场生效、不用重启**），
或者干脆用 `start-local.bat` 只监听 `127.0.0.1`。

要留意的是这里**有两套凭据，互不相干**：

| | 用在哪 | 配置项 | 出厂值 |
|---|---|---|---|
| Web 登录 | 浏览器打开控制台 | `web.user` / `web.password` | `admin` / `admin` |
| ONVIF | NVR 添加通道时填的 | `onvif.user` / `onvif.password` | `admin` / `admin` |

**改一套不会影响另一套。** 把任一套的口令设成**空串**在这程序里都不是"关掉
鉴权"，而是"口令就是空"：挑战/登录框照常出现、校验照走，任何人按一下回车就
进去了 —— 所以留空时会打 WARN。

还有一条：会话的签名密钥是**每进程一份的随机数**，不是口令本身。所以**重启
程序会把所有已登录的人踢下线**（通常正是想要的）；反过来，**改口令不会踢人**，
已经发出去的 cookie 一直有效到 7 天后过期。要立刻清空所有人，只能重启。
